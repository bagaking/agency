# Writing Techniques for EIS

Use these techniques when drafting escalation sketches.

## 1) Hook: incident already happened

Bad:
- 慢慢解释背景。

Good:
- first line asks the broken-state question directly.
- line is understandable by outsiders immediately.

## 2) Ping-Pong: short blame chain

Preferred sentence engine:
- `我问你...你说...`

Rules:
- each line adds a new misunderstanding
- no large background exposition

## 3) Escalation order

Escalate in this order when possible:

1. key people are present (boss/client/candidate/request-owner)
2. exposure channel is public (group chat/screen share/meeting)
3. context is high pressure (incident review/report/interview)
4. technical detail is garnish only

## 4) Anchor question

Use a stable order role to ask the audience's core question.

Examples:
- 老板现在看到哪一页？
- 会议室里现在什么情况？
- 客户回了没？

## 5) Cold knife ending

Final line formula:
- 门口角色 + 平静语气 + 新事实 + 更糟后果

Never end with:
- process lesson
- policy conclusion
- moral sentence

## 6) Role function map

- 压场角色: hold rhythm, ask anchor question
- 冲突角色: produce blame collisions
- 理性角色: expose contradiction
- 门口角色: deliver cold-fact tail

## 7) Self-audit checklist

- outsider readability within 1 second
- final line strictly worse than prior lines
- at least one screenshot-friendly line
- remove role names and test if joke still stands
